# 优化对比图

| 对比项 | 原 Text-to-SQL 项目 | 优化后的 AI 医管智能体 | 优化价值 |
|---|---|---|---|
| 项目定位 | 通用电商数据查询 Demo | 医院管理层运营分析助手 | 从技术演示变成行业场景项目 |
| 数据对象 | 用户、商品、订单、订单明细 | 科室、医生、门诊、住院、收费、床位、手术 | 更贴合医管业务 |
| 数据库 | `ecommerce.db` | `data/hospital.db` | 支持医院运营指标 |
| Schema | 代码 Prompt 中简单描述 | `data/hospital_schema.json` 结构化描述 | 便于模型理解表结构和指标口径 |
| 查询能力 | 销售额、订单量、库存 | 门诊量、科室收入、床位使用率、药品收入占比、平均住院日、手术量 | 覆盖医院管理层常问问题 |
| 安全控制 | Prompt 约束只允许查询 | `src/sql_guard.py` 运行时拦截非 SELECT 和危险 SQL | 更符合医疗数据安全要求 |
| 知识问答 | 无 | `hospital_docs` 指标和制度知识库 | 支持 RAG 式管理解释 |
| Agent 路由 | 单一 SQL Agent | `src/router.py` 区分 SQL/RAG/报告/混合任务 | 能处理更复杂的管理问题 |
| 分析输出 | 返回自然语言答案 | 数据表 + 异常提示 + 管理建议 | 更适合院长、科主任阅读 |
| 医保控费观察 | 无 | 模拟 DRG/DIP 病组、病例模拟支付和科室风险评分 | 展示产品对控费风险和落地边界的理解 |
| 图表展示 | 命令行输出 | Streamlit + Plotly 可视化 | 适合 Demo 展示 |
| 报告生成 | 无 | `src/report_generator.py` 月度运营简报 | 从问答升级为管理报告工具 |
| 数据来源 | 模拟电商数据 | 模拟医院运营明细 + 公开政策口径引用 | 既保护隐私，又有行业依据 |
