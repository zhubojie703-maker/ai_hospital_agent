## 视频方法论蒸馏

在让 AI 写前端之前，先完成前端骨架定义，避免页面越改越散。核心顺序是：

1. 先确定整体设计风格：视觉语言、颜色、字体、字号层级、行高、间距、圆角、卡片样式、按钮形态、页面布局和信息密度。
2. 再确定技术方案和 UI 组件策略：前端框架负责项目结构，UI 组件或自定义组件负责界面统一。
3. 提前划清目录、模块和组件边界：哪些是页面，哪些是通用组件，哪些是数据逻辑，哪些是样式规则。
4. 准备样式系统：把颜色、字体、间距、圆角、图表色板等做成 token，减少一次性样式。
5. 写进实施计划后再让 AI 搭页面：让后续页面都长在同一套规则上。

## 本项目的前端骨架

### 产品角色

本项目不是医疗诊断工具，而是面向医院运营管理的 AI 医管智能体。核心用户是院办、运营负责人、科室主任和产品/数据演示场景中的面试官。

### 视觉语言

| 项目 | 规则 |
|---|---|
| 产品气质 | 医院运营后台，安静、专业、信息密度高 |
| 主色 | 绿色作为状态色和主操作色 |
| 辅助色 | 蓝色用于趋势线，青色用于补充指标，黄色用于预警，红色用于风险 |
| 背景 | 深色后台，减少演示时的视觉干扰 |
| 卡片 | 8px 圆角，轻边框，固定 KPI 高度 |
| 字体层级 | 页面标题、面板标题、指标值、正文、标签五级 |
| 图表 | 使用统一 Plotly 色板，避免每个页面各自配色 |

### 技术骨架

| 层级 | 当前选择 |
|---|---|
| 页面框架 | Streamlit |
| 可视化 | Plotly |
| 数据处理 | pandas + SQLite |
| 问答链路 | Router + Text-to-SQL + SQL Guard + RAG |
| 桌面入口 | Tkinter 浮窗和桌面小拖件 |
| 样式系统 | `UI_TOKENS` + CSS variables + `CHART_COLORS` |

### 页面边界

| 页面 | 模块名 | 边界 |
|---|---|---|
| 运营总览 | dashboard | 管理层首屏，只放核心 KPI、趋势、风险和关键发现 |
| 浮窗问答 | floating_qa | 轻量 AI 入口，输入问题后再展示表格和图表 |
| 智能问答 | qa | 承接 Text-to-SQL、RAG 和报告类问题 |
| 趋势分析 | trends | 观察时间序列、结构占比和资源变化 |
| 科室绩效 | departments | 对比科室工作量、收入、床位和费用结构 |
| 运营简报 | report | 输出管理层可读的月度运营报告 |
| 医管知识库 | knowledge | 展示指标口径、医保控费、DRG/DIP 和绩效文档 |
| 改动记录 | change_log | 展示升级过程、差异和项目包装信息 |

### 组件复用规则

| 组件 | 复用规则 |
|---|---|
| `render_header` | 所有页面统一用标题、副标题和状态标签，不单独写页面大标题 |
| `section_title` | 面板标题统一用标题 + badge |
| `render_metric` | KPI 卡片统一高度、字号、涨跌样式 |
| `render_assistant_panel` | 右侧 AI 解读、建议动作和提示统一用同一组件 |
| `style_fig` | 所有 Plotly 图表统一背景、字体、边距和色板 |
| `PAGE_REGISTRY` | 页面先注册 label、module、purpose，再进入侧边栏和路由 |

## 后续迭代建议

1. 如果继续扩展页面，可以把 `render_metric`、`render_header`、`style_fig` 拆到 `src/ui_components.py`。
2. 如果项目继续变大，可以把 `PAGE_REGISTRY` 拆到 `src/ui_pages.py`。
3. 如果需要更像真实后台，可以增加筛选栏组件、空状态组件、异常状态组件和导出按钮组件。
4. 如果未来改成 React/Vue，可以直接沿用这份骨架文档作为前端 PRD。
