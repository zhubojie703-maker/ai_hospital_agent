# 项目经历改写建议

## 简历 bullet 版本

- 设计并实现 AI 医管智能体 Demo，将通用 Text-to-SQL 能力产品化为医院运营管理场景，覆盖运营总览、科室绩效、趋势分析、智能问答、RAG 指标知识库和月度运营简报。
- 新增“医保控费观察”模块，基于模拟 DRG/DIP 病组、模拟支付标准和病例费用记录，构建科室风险评分、费用超支病例识别和病组模拟盈亏分析，展示从数据查询到管理风险识别的产品升级路径。
- 通过 SQL Guard、指标口径文档、产品落地说明和评审清单，明确 AI 回答边界、数据安全约束和真实 DRG/DIP 落地所需数据，体现需求拆解、方案表达、原型呈现、文档对齐和评审推进能力。

## 面试口播版本

这个项目最初是一个通用 Text-to-SQL Demo，我没有停留在“能生成 SQL”这个技术点，而是把它重新定位成医院运营管理场景。围绕院办、运营负责人和科主任的高频问题，我设计了运营总览、科室绩效、趋势分析、智能问答、知识库和月度简报。

后续我又加了一个轻量版“医保控费观察”模块。这里我没有直接做正式 DRG/DIP 结算，因为真实落地需要病案首页、医保结算清单、诊断和手术编码、本地分组规则和支付标准。当前版本是用模拟病组、模拟支付金额和病例费用记录，展示如何把药占比、耗材占比、平均住院日、费用超支和模拟亏损转化成科室风险评分。

这个项目主要体现的是我的产品落地能力：我能从业务问题出发，拆出用户角色和核心场景；能把 AI 能力放进可演示的业务流程；也能通过文档和评审清单说明当前边界和后续真实落地条件。

## 作品集展示结构

1. **背景**：从通用 Text-to-SQL 升级为医院运营管理助手。
2. **用户**：院办、运营负责人、科主任、医保办/绩效人员。
3. **痛点**：查数慢、指标口径不统一、异常难追踪、报告依赖人工。
4. **方案**：Text-to-SQL + SQL Guard + RAG + 看板 + 简报 + 医保控费观察。
5. **原型闭环**：看运营总览，进入科室绩效，查看医保控费观察，生成运营简报。
6. **边界**：当前为模拟控费观察，不做正式 DRG/DIP 结算预测。
7. **迭代**：接入病案首页、医保结算清单和本地分组规则后，可扩展为更真实的控费风控系统。

## STAR 讲法

- **S 场景**：原项目只是通用数据问答，行业场景和产品价值不够清晰。
- **T 任务**：需要把 AI 查数能力包装成更像真实业务系统的医管产品原型。
- **A 行动**：重构医院运营数据模型，设计看板、问答、知识库、简报，并新增轻量医保控费观察模块。
- **R 结果**：项目从技术 Demo 升级为可评审的 AI 医管产品原型，能展示需求理解、产品设计、数据建模和落地边界意识。
