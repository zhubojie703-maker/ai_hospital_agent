# AI 医管智能体产品落地说明

## 项目定位

本项目是面向作品集和面试展示的 AI 医管产品原型。核心目标不是做正式医疗诊断或医保结算，而是展示如何把通用 Text-to-SQL 能力，落到医院运营管理、医保控费观察和管理报告生成场景中。

## 目标用户

| 用户 | 关注问题 | 本项目对应能力 |
|---|---|---|
| 院办/运营负责人 | 哪些科室经营指标异常，如何形成月度管理简报 | 运营总览、趋势分析、运营简报 |
| 科主任 | 本科室工作量、床位效率和费用结构是否异常 | 科室绩效、费用结构风险 |
| 医保办/绩效人员 | 哪些科室可能存在费用超支、住院日偏长和模拟亏损风险 | 医保控费观察、风险评分 |
| 数据/产品评审方 | 数据口径、AI 边界和后续真实落地条件是否清楚 | 指标知识库、评审清单、边界说明 |

## 核心业务闭环

1. 运营总览发现床位、收入或费用结构异常。
2. 进入科室绩效页对比工作量、收入、药占比、耗材占比和平均住院日。
3. 进入医保控费观察页查看科室风险分、模拟 DRG/DIP 亏损和费用超支病例。
4. 通过医管知识库理解指标口径和医保控费管理含义。
5. 生成运营简报，把风险点沉淀为管理层可读的建议。

## 轻量 DRG/DIP 设计边界

当前版本只做“医保控费观察”，不做正式 DRG/DIP 结算预测。系统新增模拟病组、模拟支付标准和病例费用记录，用于演示产品如何把运营指标转为风险优先级。

真实 DRG/DIP 落地还需要：

- 病案首页、诊断编码、手术编码
- 医保结算清单和本地分组规则
- 支付标准、特例单议规则和审核规则
- 病例成本、耗材准入、临床路径和质量安全指标

## 本次升级体现的能力

- **需求理解**：从“能查医院数据”升级到“管理者需要发现经营和控费风险”。
- **产品设计**：新增风险评分、风险排行、病组观察和报告章节，形成业务闭环。
- **数据建模**：新增模拟病组、病例模拟支付和风险规则表，支撑控费观察。
- **原型呈现**：新增“医保控费观察”页面，把复杂风险变成可评审表格和图表。
- **落地边界意识**：明确当前只是模拟观察，不夸大为正式 DRG/DIP 结算。

## 后续迭代方向

1. 接入真实或更高保真的病案首页字段，支持诊断和手术编码维度分析。
2. 增加整改任务闭环：风险发现、科室确认、医保办复核、处理结果沉淀。
3. 增加指标阈值配置，让医院可按本地规则调整风险权重。
4. 增加导出功能，把运营简报和控费观察结果导出为评审材料。
